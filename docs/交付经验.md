# pppic 交付经验

## 受限环境下分层验证

本次 Node 服务监听本机端口返回 EPERM；直接运行常规集成测试会把全部接口用例错误标记为业务失败。将 Request 的实际 multipart 序列化后注入同一 Node handler，可以继续验证鉴权、表单、数据库和真实文件读写。该方式已通过 16 项测试，但必须与真实 HTTP、浏览器和云服务实测分开报告。

复用方式：先 `npm test`；在具备端口权限的环境使用 `npm run test:http`；再运行 Playwright。不要通过关闭断言或跳过错误用例来制造“全部通过”。

## 对象与元数据一致性

上传先写文件再落库，删除先删文件再删记录。进程内串行化写操作可以保护单实例的去重和配额。文件系统与 SQLite 不构成跨存储事务：崩溃可能留下孤儿对象或失效记录，应写清恢复边界，不能宣称严格原子性。

本地文件采用临时写入后原子替换，避免正常写入失败留下最终路径上的半文件；进程突然退出仍可能留下 `.upload-*` 临时文件，停机核实后可以清理，不能直接当作图库记录删除。

## 私有图库与公开分享

图库需要认证，但公开图片 URL 必须能用于外站引用；管理员密钥与应用密钥分开管理。上传能力不应自然包含读取/删除能力。已用权限矩阵及撤销测试验证边界。

## 配置参与接口行为

PUBLIC_URL 同时决定分享链接和 cookie 写请求的来源校验。localhost 与 127.0.0.1、HTTP 与 HTTPS、不同端口均不是同一个源；部署文档需要给出这个具体关系，避免“能登录但无法写入”的配置错误。
