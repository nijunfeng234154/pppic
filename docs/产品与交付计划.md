# pppic 产品与交付计划

## 输入与目标

用户要求：使用 AI-Fullstack-Delivery-Workflow，为空目录 pppic 开发同时支持 Web 和 API 的万能图床。

首版假设：单管理员自托管，图库和管理接口私有，分享链接公开；本地存储默认可用，S3 兼容存储通过环境变量接入。未指定品牌、技术栈和部署账号，采用可独立运行的轻量方案，不执行生产部署。

## 用户故事与可测标准

1. 管理员使用启动生成的管理口令登录，浏览器不在 localStorage 存储口令；未登录不能查看图库、上传或删除。
2. 用户拖拽、选择或粘贴多张图片，每张独立显示进度和失败原因；成功后可复制 URL、Markdown、HTML、BBCode。
3. 支持 PNG、JPEG、GIF、WebP、AVIF；检查文件头，不以扩展名或浏览器 MIME 为唯一依据。默认每张不超过 20 MiB，最多 4 个并发上传请求；拒绝 SVG 和非图片。
4. 图片按 SHA-256 去重，同一文件并发上传不会重复占用空间；查询支持文件名、相册、格式、收藏和分页。
5. 删除图片后公开链接不可用；删除文件失败时保留元数据，允许重试。
6. 可创建 upload（上传）、read（只读）、manage（图片管理）权限的 API 密钥；密钥不能管理其他密钥，撤销立即生效。
7. 文件存储与数据库分离：本地文件和 S3 对象均通过应用公开链接读取，不需要公开桶。

## 范围与风险

本版交付单租户版本。暂不包含公开匿名上传、URL 抓取、多用户注册、计费、图片转码、病毒扫描、图片内容审核和 CDN 管理。格式识别是文件头校验，不是完整解码或恶意内容扫描；原图可能含 EXIF 隐私信息。S3 需真实账号配置后验收，不能把 mock 测试当作云服务实测。

SQLite 适用于单实例、低中等并发；内置模块在本机 Node 24.10 仍有实验性提示。无生产 npm 依赖，便于离线部署；这是一项针对空项目与当前环境的选型例外，后续规模增长再迁移 PostgreSQL/流式上传。
