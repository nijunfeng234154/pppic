# 部署与回滚

## Docker Compose 本机部署

需要 Docker Engine 和 Compose v2；使用根目录 `docker-compose.yaml`。首次部署先按 README 克隆仓库并创建 `.env`；已有配置不要覆盖。以下配置需在有容器权限的主机执行，本次未实测构建镜像。

```bash
docker compose -f docker-compose.yaml up -d --build --wait
docker compose -f docker-compose.yaml logs --tail=50 pppic
docker compose -f docker-compose.yaml exec pppic cat /app/data/admin-token
curl --fail http://localhost:3333/healthz
```

访问 http://localhost:3333 登录。使用自定义 ADMIN_TOKEN 时，使用你配置的口令，不会生成 admin-token 文件。数据位于持久卷 `pppic_data`，不要执行 `docker compose -f docker-compose.yaml down -v`，该命令会删除数据卷。

若修改 PORT，PUBLIC_URL 也应填写外部实际端口。默认只将容器端口绑定到主机 127.0.0.1，公网部署通过反向代理接入。

## 公网域名

配置 `.env` 中 PUBLIC_URL 为实际 HTTPS 域名，COOKIE_SECURE=true。反向代理转发到主机 127.0.0.1:3333，保留浏览器的 Origin。TLS（传输层加密）由代理终止。以下为 Nginx 站点中的 location 示例，证书配置由已有环境提供：

```nginx
location / {
    proxy_pass http://127.0.0.1:3333;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    client_max_body_size 21m;
    proxy_read_timeout 65s;
    proxy_send_timeout 65s;
}
```

默认上传上限为 20 MiB，21m 为表单开销留余量。增加应用上限时同步调整代理和容器内存。S3 凭证通过部署环境注入，使用只允许指定桶对象读写删除的最小权限凭证。

## 发布验收

1. `/healthz` 返回 200。
2. 未登录访问 `/api/v1/images` 返回 401。
3. 使用 Web 登录，上传一张测试图片，在未登录浏览器打开直链。
4. 创建 upload 密钥，执行 README 的 curl 上传；确认该密钥无法 DELETE 图片。
5. 删除测试图片后直链返回 404，撤销密钥后返回 401。
6. 重启应用，确认图片与密钥仍存在；启用 S3 时在真实桶完成相同流程。

CI 在 push 和 pull_request 时执行语法检查、真实 HTTP 接口测试和桌面/移动端 Playwright 测试；失败阻止本次检查通过，不会自动部署生产。目标远程仓库为 `https://github.com/nijunfeng234154/pppic.git`；本环境尚未成功推送，CI 尚未验证。

## 备份与恢复

需要同时备份 SQLite、admin-token 和 uploads；使用 S3 时还需开启桶版本管理或独立对象备份，仅备份数据库不足以恢复图片。

最简单的一致性备份方式是停机后导出完整数据卷，以下备份文件保存到当前目录的 backups：

```bash
mkdir -p backups
docker compose -f docker-compose.yaml stop pppic
docker compose -f docker-compose.yaml run --rm --no-deps -T pppic tar -C /app/data -czf - . > backups/pppic-data.tar.gz
docker compose -f docker-compose.yaml start pppic
```

每次使用新的备份文件名，避免覆盖旧备份。归档包含管理口令和业务数据，限制访问，不要提交到仓库。停机可避免遗漏 WAL 中尚未合并的写入；完整目录中的 sqlite、-wal、-shm 应一起保留。恢复前保留当前数据副本，先在独立卷验证归档及对象备份，再切换应用。

## 回滚

发布前保留上一版镜像与完整数据备份。若新版本失败：停止服务，用已知正常的上一版源码/镜像重新启动，并检查健康和一次上传读图流程。本版 schema=1；未来若发生不兼容迁移，应恢复匹配的数据库和对象快照，不能只回滚镜像。恢复会丢失备份之后的变更，需先保留故障现场并核对需要恢复的时间点。

应用日志写入 stdout/stderr，Docker Compose 查看；错误包含 request_id，可与客户端错误响应关联。默认 JSON 日志轮转最大 10MB × 3 文件。
