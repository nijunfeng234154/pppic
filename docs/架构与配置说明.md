# 架构与配置说明

## 架构

浏览器原生 JavaScript → 同源 Node HTTP API → SQLite 元数据 + 本地文件/S3 对象。无前端构建步骤，无生产 npm 依赖。原图使用流式读取；上传按单请求限制大小，最多 4 个并发请求，Web 队列最多 3 个并发任务。图片写入与删除在进程内排队，避免并发去重和配额竞态。

单租户权限：管理员管理所有图片和密钥；upload 只上传，read 仅读取，manage 可执行图片上传、读取、编辑和删除，所有 API 密钥均不可管理其他密钥。

## 数据模型

| 表 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| images | id, name, hash, ext, mime, size, object_key, driver, album, favorite, created_at | hash/object_key 唯一；时间及相册索引支持查询 |
| api_keys | id, name, prefix, hash, scope, created_at, last_used_at | 仅存 SHA-256 哈希；原文仅创建时返回 |
| sessions | hash, expires_at | 7 天会话；按哈希查询，定期清理过期会话 |

SQLite 开启 WAL（预写式日志）和 busy_timeout。首次启动自动建表，schema 版本为 1，保存在 PRAGMA user_version；拒绝打开版本高于 1 的数据库。当前没有旧系统数据，不涉及破坏性迁移。后续版本迁移必须先备份并提供兼容性和恢复步骤。

本地文件名由内容 SHA-256 和识别出的格式组成，与用户提供的文件名分离；用户文件名只作为元数据。公开 URL 使用随机 UUID，与底层文件路径分离。

## 配置项

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| HOST | 127.0.0.1 | 本地监听地址；容器内用 0.0.0.0 |
| PORT | 3333 | HTTP 端口 |
| PUBLIC_URL | http://localhost:3333 | 公开源地址，生成直链、校验 Origin；不接受路径/查询/片段 |
| DATA_DIR | ./data | 数据库、初始管理口令、本地图片位置 |
| ADMIN_TOKEN | 自动生成 | 24–512 字符，不含空白；使用高熵随机字符串 |
| MAX_UPLOAD_MB | 20 | 单文件上限，1–100 MiB |
| STORAGE_LIMIT_MB | 10240 | 全图库逻辑配额，1–10485760 MiB，不是磁盘实际剩余空间 |
| COOKIE_SECURE | false | https PUBLIC_URL 时自动启用 Secure cookie |
| STORAGE_DRIVER | local | local 或 s3，新上传使用此驱动 |
| S3_ENDPOINT | 空 | 例如 R2 的 HTTPS S3 endpoint；不包含桶名或查询参数 |
| S3_REGION | auto | AWS 使用桶所在 region；R2 通常使用 auto |
| S3_BUCKET | 空 | 预先创建的私有桶 |
| S3_ACCESS_KEY_ID | 空 | 专用存储凭证 |
| S3_SECRET_ACCESS_KEY | 空 | 专用存储密钥 |

`S3_ENDPOINT` 采用 path-style（桶名放入路径）寻址，使用 AWS SigV4（第 4 版请求签名），不支持临时会话凭证。云服务若只支持虚拟主机寻址，需要另行适配。仅当启用 s3 时强制校验所需配置。

切换存储驱动只影响新上传。记录保留原驱动；旧图仍需保留对应配置及文件。若变更 S3 endpoint 或 bucket，必须迁移对象后再变更，本版没有多桶映射或自动迁移。相同内容全局去重，切换驱动后再次上传不会搬迁已有图片。

## 一致性与失败处理

- 上传先写对象，成功后插入数据库；插入失败尝试清理对象。进程在两步之间崩溃可能产生孤儿对象，本地同内容文件会在重试时校验并复用。
- 删除先删对象，再删数据库；对象删除失败保留记录。进程在两步之间崩溃可能短暂留下失效记录，可重试删除恢复。
- 数据库不是对象存储的分布式事务；不能承诺断电情况下严格原子性。
- `/healthz` 检查进程和数据库，不探测云存储；上线验收必须执行真实上传/读取/删除。
- 所有管理接口返回 no-store。原图支持 ETag，但要求每次重新验证，删除后不继续使用浏览器的新鲜缓存。

## 安全与限制

会话使用 HttpOnly、SameSite=Strict；cookie 写请求必须携带匹配 PUBLIC_URL 的 Origin。API 使用 Bearer 密钥，默认不开放 CORS。登录按直连 IP 限制 15 分钟最多 10 次尝试；反向代理下所有请求可能共享代理 IP，不信任任意客户端的 X-Forwarded-For，公网限流应在受信任代理配置。

SQLite 使用参数化查询，文件路径使用受限内容哈希，响应启用内容安全策略与 nosniff。图库数据对外不可匿名查询，但直链公开；格式验证只检查签名，不完整解码，不清理 EXIF。数据库内 API 密钥和会话仅保存哈希，管理口令默认保存在权限 0600 的本机文件。
